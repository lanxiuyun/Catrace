# 当前 Toast Window 逻辑

Toast 不是小卡片窗。Windows 上它是一块铺满**光标所在显示器工作区**的透明覆盖层；卡片只是这块层里右下角的 DOM。点击默认整窗穿透，只有卡片矩形可交互。

## 1. 窗口身份与属性

- Label：`reminder-toast`（`src-tauri/src/window_manager/shared.rs`）
- 启动时预创建、默认隐藏：`prepare_toast_window`（`lib.rs` setup → `reminder_toast.rs`）
- URL：`index.html#/reminder-toast` → `ReminderToast.vue`
- Builder：无边框、透明、always_on_top、不抢焦点、不进任务栏、不可最大化/缩放、shadow=false、初始 `inner_size(360,160)`（随后立刻被 fit 成工作区大小）
- Toast/Popup 关窗只 **hide 复用**，不 destroy（`close_reminder_window`）。下次显示走 reuse，避免重建抢焦点。

macOS 暂无 Win32 无焦点/subclass；show 走普通 `show()`，穿透走 tao `set_ignore_cursor_events`。

## 2. 数据流（内容 vs 窗口）

```
Producer (rest / agent / plugin / HTTP SDK …)
  → EventBus.publish(BusEvent)
      → display_mode=Toast 时 ensure_toast_window_visible（只管窗，不 eval 内容）
      → emit catrace:event
          → ReminderToast.handleBusEvent → addNotification / 原地 upsert
```

约定：

- Toast 是**可见权威**；bus 失败不挡窗（agent/update/permission 的 `try_publish` 失败会兜底 `ensure_toast_window_visible`）。
- 主窗 `eventHub` 只观察，**不渲第二张卡**。
- 禁止主路径 `eval addToastNotification`。`create_toast_window` 仍在，标 `dead_code`，legacy。
- Toast 窗晚到：`getActiveEvents()` 水合。

## 3. 位置：谁算、怎么算

**Rust 钉窗，前端钉卡片。**

`fit_toast_window_to_cursor_monitor`：

1. `available_monitors()`
2. 有辅助功能权限：用 `device_query` 读光标物理坐标，命中哪块屏用哪块；否则第一块屏
3. 用 `monitor.work_area()`（避开任务栏 / Dock），**物理像素**
4. Windows：`set_window_rect_physical` → 一次 `SetWindowPos(x,y,w,h)`，不走 tao 分步 `set_size`/`set_position`

前端 `.toast-root`：`100vw × 100vh`，`flex-end` 把 `.toast-stack` 贴右下，padding `1rem`。卡片宽 `22.5rem`。堆叠 = 数组顺序，新卡 push 到底部，多卡时 `scrollTop = scrollHeight`。

**不做**前端 `setPosition` 贴右下角（旧路径注释已写明：两边 reposition 会打架）。

## 4. 显示 / 隐藏 / 堆叠

**显示** `ensure_toast_window_visible`：

- 已可见 → return（连点堆叠不反复 show）
- 存在但隐藏 → `TOAST_MUTEX` 串行 → eval 保证 hash → **重新 fit 到光标屏** → 强制穿透 → `ShowWindow(SW_SHOWNOACTIVATE)` + `WS_EX_NOACTIVATE`（不推 HWND_TOPMOST，避免全屏游戏被切出）
- 被销毁 → rebuild 同一套属性

**隐藏**：栈空 → `closeReminderWindow('reminder-toast')` → hide。穿透轮询见 hidden 后强制 `ignore=true`。

**堆叠规则（前端）**：

- 同 `event.id`：`seenBusEventIds` 去重
- 同 `dedupe_key`：原地刷新，不抖窗
- hover 中新消息：只改内容，**不重置倒计时**
- sticky agent 多 session 合并一张卡
- rest-timer / sdk / plugin：upsert in place，避免 PluginHostCard remount 冻窗
- 非 sticky 默认 8s auto-hide（payload 可改，clamp 3s–10min）；hover 暂停；`catrace:toast-hover-exit` 补 mouseleave
- 离场只切 `.leaving` 淡出，**不做 FLIP**（透明 WebView2 合成器会冻）

## 5. 点击穿透（Windows 关键）

覆盖层默认吞整屏点击，所以：

1. `WS_EX_TRANSPARENT` + 强制保留 `WS_EX_LAYERED`
2. `WM_NCHITTEST` subclass：穿透态返回 `HTTRANSPARENT`（tao 自己吃 hit-test，单靠 EX_TRANSPARENT 不够）
3. **禁止** tao `set_ignore_cursor_events`：它 `apply_diff` 会按未同步的 VISIBLE 把窗 `SW_HIDE`，并丢掉 LAYERED

前端每 200ms + ResizeObserver 上报卡片 `getBoundingClientRect()`（CSS px）→ `set_toast_hit_regions`。滚动条竖条也算 hit。

后台线程 50ms：光标物理坐标 vs `window.inner_position + rect * scale_factor`。命中 → 取消穿透；离开 → 穿透 + emit hover-exit。每 tick **强制同步**样式（tao 随时冲掉 EX_TRANSPARENT）。

`TOAST_IGNORING` 由 show 路径和 poll 共享。

## 6. 切屏 / DPI（#56 已修）

旧 bug：光标到副屏后**第一张** Toast 偏移且无法点。

原因：`work_area()` 物理像素先 ÷ 目标屏 scale 成逻辑，再 `set_position`/`set_size`。切屏瞬间窗还挂在**旧 DPI**，tao 按旧 scale 转回物理 → 位置错。hit 矩形跟着错 → 一直穿透。

更深层：一次 `SetWindowPos` 同步触发 `WM_DPICHANGED`，tao 为「保持逻辑尺寸」再改物理大小，覆盖层小于工作区。

现路径：

- 直接钉物理 `work_area`
- `SetWindowPos` 后 `GetWindowRect` 对不上就再钉一次（第二次时 DPI 已是目标屏）
- `ScaleFactorChanged` 且窗可见 → 立刻再 fit（`TOAST_REFITTING` 防重入）
- show 前每次 reuse 都 fit + 强制穿透

## 7. 文件分工

| 层 | 文件 | 职责 |
|----|------|------|
| 生命周期 / fit / hit poll | `src-tauri/src/reminder_toast.rs` | prepare / ensure / fit / hit-rects / hover-exit |
| Win32 | `window_manager/windows.rs` | SetWindowPos 双写、穿透、NOACTIVATE、show/hide |
| Bus | `bus.rs` | publish → ensure + emit |
| 内容 UI | `src/views/toastWindows/ReminderToast.vue` | 订阅、堆叠、计时、上报 hit |
| 壳 | `ToastShell.vue` | 透明 html/body |
| 主窗 | `src/stores/eventHub.ts` | 只观察 |

## 8. 边界

- 无辅助功能权限：fit 落到第一块屏，不跟光标
- popup / fullscreen 久坐模式不走这条 Toast 窗
- 调试黄底：`catrace-toast-debug-changed`，Rust 背景永远透明
