# 主窗切页动画与布局路由约定

> 现状是 React 壳（`src/app/`）。Vue 时代的 `App.vue` / `MainShell.vue` 已删除，本文只描述现在的实现。

## 结构：MainShell 是布局路由

主窗四条一级页面（dashboard / plugins / settings / debug）挂在同一个 `/` 布局路由下，壳用 `<Outlet />` 渲染当前页面：

```tsx
createHashRouter([
  {
    path: '/',
    element: <MainShell />, // 侧栏 + <Outlet /> + <Toaster />
    children: [
      { index: true, element: <Navigate to="/dashboard" replace /> },
      { path: 'dashboard', element: <Dashboard /> },
      { path: 'plugins', element: <Plugins /> },
      { path: 'settings', element: <Settings /> },
      { path: 'debug', element: <Debug /> },
    ],
  },
  // toast / 插件宿主窗仍是顶层路由，走 ToastShell
])
```

**不要再给每条路由单独包一层 `<MainShell>`**：那样每切一次页侧栏都会重建，选中态、键盘焦点和挂在壳里的 `<Toaster />` 都会被重置，快照里的侧栏也会跟着淡入淡出。

## 切页动画：View Transitions

- 导航项是 `<NavLink viewTransition>`：由 react-router 内部调用 `document.startViewTransition`，浏览器给旧/新状态各拍一张快照再交叉淡化。
- 规则统一写在 `src/app/shell/shell.css` 的 `::view-transition-old(root)` / `::view-transition-new(root)`：旧页 140ms 淡出、新页 200ms 淡入，都是 `ease-out`。插件中心「列表 ↔ 详情」沿用同一套时长，两处切换手感一致。
- `::view-transition-*` 是文档级伪元素，页面自己的 CSS 里不要再写一份；页面内非路由的状态切换（比如插件列表 ↔ 详情）需要同样效果时，用 `PluginCenter.tsx` 里 `runViewTransition` 那种 `startViewTransition + flushSync` 包装。
- 没有 View Transitions API 的 WebView（老 WebView2 / macOS Safari < 18）不报错，直接瞬切，所以动画不是功能依赖。
- `prefers-reduced-motion: reduce` 下 `animation: none`，保持瞬切。
- 弹窗走 portal，属于 root 快照，同样被这层淡入覆盖。**不要**改成给某个页面容器单独命名 `view-transition-name`，否则 portal 内容会绕开过渡。

## 故意不做的事

- 不做左右滑动 / 方向性转场：一级导航之间没有空间顺序，方向性位移会误导用户，纯交叉淡化更贴近 macOS 标签页的性格。
- 不给侧栏做「滑动选中指示器」：选中态是每个导航项自己的背景色，切页时由淡入完成，不额外引入测量逻辑。

## 涉及文件

- `src/app/shell/MainShell.tsx` — 布局组件、导航项 `viewTransition`、`<Outlet />`
- `src/app/router.tsx` — 主窗布局路由
- `src/app/shell/shell.css` — 切页淡入淡出规则与 reduced-motion 降级
- `src/app/pages/plugins.css` — 插件页自己的过渡规则已收敛到 shell.css
