# 2026-08-27 Toast 小窗增高时卡片闪到任务栏

## 现象

Toast 小窗内容增加（如展开详情、新增卡片）导致窗口增高时，卡片会短暂闪到任务栏下方，随后才回到正确位置。

## 根因

窗口底边需要始终锚定在 `work_area` 底边（避免超出屏幕）。直接一次 `SetWindowPos(x, y, width, height)` 在 WebView2/tao 内部可能按「先改尺寸、后改位置」的顺序执行：

1. 窗口高度从 160 变成 300
2. 顶部 y 坐标还没变 → 底部向下延伸进入任务栏
3. 随后 y 坐标上移到新位置 → 卡片才回到可见区

这个中间态就是用户看到的「闪到任务栏」。

## 修复

在 `set_window_rect_physical` 里分两步：

```rust
if h > old_h {
    // 增高：先上移（保持旧高度），再拉高
    apply_window_rect(hwnd, x, y, old_w, old_h);
    apply_window_rect(hwnd, x, y, w, h);
} else if h < old_h {
    // 缩短：先压高度，再下移
    apply_window_rect(hwnd, rect.left, rect.top, w, h);
    apply_window_rect(hwnd, x, y, w, h);
}
```

同时前端把 `.toast-root` 的 `justify-content` 从 `flex-end` 改为 `flex-start`：窗口增高时，多出来的是透明顶部而不是卡片底部，即使 Rust 两步调整之间有微小延迟，卡片也不会进任务栏。

## 关键文件

- `src-tauri/src/window_manager/windows.rs` — `set_window_rect_physical` 的两步 resize 逻辑
- `src/views/toastWindows/ReminderToast.vue` — `.toast-root` 贴顶布局

## 教训

- WebView2 / tao 的 `SetWindowPos` 调用顺序不能假设原子性；视觉敏感的 resize 需要在应用层拆成「先移后拉」或「先压后移」
- 前端布局方向也要配合：让可变尺寸发生在远离锚边的一侧
