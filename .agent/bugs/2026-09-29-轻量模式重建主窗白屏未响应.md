# 轻量模式从托盘重开主窗：白屏「未响应」卡死

**日期**：2026-09-29
**状态**：已修

## 症状

轻量模式关掉主窗后，点托盘「显示主窗口」→ 主窗壳出来了但整片白、标题栏显示「Catrace (未响应)」，进程没崩但主线程永久卡住。

日志停在重建开始那一步：`main window missing, rebuilding (lightweight mode)` 之后**没有** `main window built, showing`，说明卡在 `WebviewWindowBuilder::build()` 里没返回。同一时刻 tokio 侧还活着（`settle` 心跳照常打），是主事件循环被堵死。

## 复现

`PostMessage(WM_CLOSE)` 模拟点关闭按钮 → 二次启动 exe 触发单实例重建回调 → `IsHungAppWindow` 检测。**旧代码压测第 3 轮稳定复现**（前两轮正常，第三轮卡住），不是每次必现，所以手点几次很容易漏掉。

## 根因

初版重建路径有两个与「已验证可行」的窗口创建模式不一致的地方：

1. builder **创建即可见**（没有 `.visible(false)` 先隐藏）；
2. build 之后**手动调了 `restore_state`** 恢复窗口几何，而 window-state 插件本来就会在每个窗口的 `on_window_ready` 里自动 restore —— 等于对同一个窗口重复走恢复流程。

对比参照：fullscreen 提醒窗、插件后台窗都是「先隐藏创建、再显示」，从未卡死；差异就是这两点。

## 修复

`show_or_rebuild_main_window` 的异步重建（`src-tauri/src/lib.rs`）：

- builder 加 `.visible(false)`，`build()` 成功后再 `show()` + `set_focus()`；
- **删掉手动 `restore_state`**，位置尺寸交给 window-state 插件的 `on_window_ready`；
- 重建后仍必须重新挂 `attach_main_window_events`（否则普通模式下重建的窗口关闭会直接销毁）。

## 验证

修复版连跑 3 轮「关闭 → 销毁 → 托盘重建」，`IsHungAppWindow` 全为 false；日志走完 `built, showing` → `rebuilt`。
