# 详细热力图 hover 重渲染 1440 格，鼠标事件卡死十几秒

## 症状

在「详细」视图的 24×60 分钟热力图上连点几下鼠标后，鼠标 hover / 点击完全失效（整页没有 hover 反馈、点击无响应），约 10 秒后自行恢复。期间当前分钟的蓝色呼吸环还在动 —— 画面在出帧，说明渲染没死，是输入事件被排到了后面。

## 根因

三件事叠在一起，把渲染主线程占满了：

1. **hover 触发 1440 个格子的 React 协调**：`mousemove` 更新 `hoveredIndex`，父组件重渲染，每次都要创建 1440 个格子元素并做 prop 比较（`memo` 只能跳过子组件渲染，跳过不了这层协调）。
2. **悬停样式带 `z-index`**：给单个格子加 `z-index` 会改变层叠顺序，整张网格（1440 格）的绘制失效，鼠标每移一格就整片重绘。
3. **当前分钟用 `box-shadow` 关键帧做呼吸**：每秒约 60 帧都在重绘网格。

主线程被渲染/重绘占满后鼠标事件排队；合成层动画（呼吸环）还能出帧，所以表现为「画面在动、光标没反应」。

## 修复

文件：`src/app/pages/dashboard/TimelineGrid.tsx`、`timeline-grid.css`

- 1440 个格子收进 `Cells`（`memo`），只依赖分钟数据；hover 不再重渲染它们。
- 悬停改成纯 CSS：`.cell:hover { outline: 1px solid var(--ct-text) }` —— 不经过 React、不改 `z-index`、不加过渡，只脏当前这一格。
- 当前分钟改成独立的绝对定位覆盖环 `.now-ring`，只做 `transform` / `opacity` 的合成层动画，不再用 `box-shadow` 关键帧。
- 同一格不重复 `setState`：鼠标在格子边缘抖动时不触发渲染。

现在一次 `mousemove` 只会更新底部的读数和那个覆盖环，格子层是静态的。

## 验证

- 详细视图里快速连点、来回扫鼠标：hover 与读数持续跟手，无卡死。
- 当前分钟蓝环正常呼吸，且不引起整张网格重绘。
- `pnpm vue-tsc --noEmit`、`pnpm build` 通过。
