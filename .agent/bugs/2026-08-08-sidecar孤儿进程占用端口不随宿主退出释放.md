# 2026-08-08 sidecar 孤儿进程占用端口不随宿主退出释放

## 症状

SmsForwarder 插件（`smsforwarder-notify`）的 sidecar 监听 `17890` 端口。
**Catrace 退出后端口仍被占用**，再次启动 / reload / disable 插件时新 sidecar 起不来或要反复抢端口。

## 根因

- sidecar 是 Catrace（Rust）spawn 的**子进程**；Windows 上父进程退出**不会自动回收子进程**。
- 宿主正常退出时走 `Drop for PluginSidecarManager → stop_all → stop_sidecar`（发 `shutdown` + `taskkill /T /F`），能清干净；但 **崩溃 / 强杀 / 更新重启时 `Drop` 不执行**，node 孤儿进程就留在原地继续 hold 端口。
- 插件侧 `runtime/main.mjs` 已有 `freePort()`（bind 撞 `EADDRINUSE` 时杀占用者），但它只在**新进程尝试 bind** 时才触发，disable 时插件自己已被停，救不了自己。

## 修复（宿主内做）

在 `src-tauri/src/plugin_sidecar.rs`：

- spawn 每个 sidecar 时挂 Windows **Job Object**，设 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，再 `AssignProcessToJobObject` 把子进程丢进 job。
- 只要 Catrace 进程存活，job 句柄就开着；**Catrace 一退出（任何方式），OS 自动关闭句柄 → 杀光 job 内整棵进程树**。
- 与原有 graceful `shutdown` + `taskkill /T /F` 叠加：正常路径优雅退出，异常路径 OS 兜底。

## 为什么在宿主做（不靠插件）

| 位置 | 能力 | 结论 |
|------|------|------|
| 宿主 | 掌握 sidecar 生命周期（spawn/disable/reload/退出），能保证无论宿主怎么死都由 OS 回收 | **治本** |
| 插件 | 只能在自身运行期 bind 撞 EADDRINUSE 时兜底清理；disable 时已死，无法自救 | 兜底，保留 |

## 涉及文件

- `src-tauri/Cargo.toml` — windows 依赖加 `Win32_System_JobObjects`、`Win32_Security`
- `src-tauri/src/plugin_sidecar.rs` — `SidecarJob`（RAII job 句柄）+ `create_and_assign` + `RunningSidecar.job`
