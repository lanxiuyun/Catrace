# Toast 全屏覆盖层空白区域无法点击穿透

**日期**：2026-08-11
**状态**：已修复（提交 `a963db6`）

## 症状

Toast 改为全屏覆盖窗后：光标移到卡片上能正常交互（hover / 点击），但空白区域无法点击穿透 —— 下层应用点不到，像整窗盖了透明玻璃板。

## 排查过程

1. 日志显示 `raw style ... after=0x... transparent=true`：`WS_EX_TRANSPARENT` 明明已设置成功，点击仍不穿透。
2. 怀疑轮询状态机与真实样式失步（tao `apply_diff` 会冲掉样式）→ 先改成每 tick 强制同步，仍不解决。
3. 最终定位根因：**tao/winit 自己处理 `WM_NCHITTEST`（为 resize/拖动返回 HTCLIENT），不落到 `DefWindowProc`**。`WS_EX_TRANSPARENT` 的点击穿透语义靠 DefWindowProc 兑现，被 tao 拦截后永远失效。

## 根因

`WS_EX_TRANSPARENT`（以及 `set_ignore_cursor_events` 走 tao）在 WebView2 窗口上都不可靠：

- tao 的 `set_ignore_cursor_events` → `apply_diff` 重建 exstyle + 检查 VISIBLE 标志（本窗口用原生 `SW_SHOWNOACTIVATE` 显示，VISIBLE 未同步）→ 窗口 `SW_HIDE` + 丢 `WS_EX_LAYERED`
- 即使手动 `SetWindowLongPtrW` 设了 `WS_EX_TRANSPARENT`，tao 拦截 `WM_NCHITTEST` 不回 DefWindowProc → 样式位不生效

## 修复

1. `set_ignore_cursor_events_raw`：只切 `WS_EX_TRANSPARENT` 一位，强制补回 `WS_EX_LAYERED`
2. `SetWindowSubclass` 挂 `WM_NCHITTEST`：穿透态返回 `HTTRANSPARENT`(-1)，交互态 `DefSubclassProc`（绕过 tao，最终保证）
3. 穿透轮询每 50ms 无条件调 raw（自愈 apply_diff 冲样）
