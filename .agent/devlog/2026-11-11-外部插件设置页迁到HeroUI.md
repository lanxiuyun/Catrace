# 2026-11-11 外部插件设置页迁到 HeroUI

## 会话目标

宿主界面已经是 HeroUI v3，但插件详情页里外部插件的设置面板还是 Radix / 手写控件，和内置的久坐提醒设置看着不像同一套 UI。目标：让外部插件设置页直接用宿主的 HeroUI 组件，同时保持插件业务逻辑与 Toast 卡片不动。

## 完成项

- [pluginRuntime.ts](../../src/plugins/pluginRuntime.ts) 在原有 `__CATRACE_REACT__` / `__CATRACE_RADIX__` 之外注入 `__CATRACE_HEROUI__`（宿主自己的 `@heroui/react` 命名空间）；Radix 继续注入给尚未迁移的 Card 与旧设置页。
- [test-react-plugin-packages.mjs](../../scripts/test-react-plugin-packages.mjs)：运行时 stub 补 `__CATRACE_HEROUI__`，新增「自包含插件模块可以渲染 HeroUI 组件」用例（真实 React + 真实 HeroUI SSR），并把 `manifest.version` 的写死日期断言改成日期格式断言。
- catrace-plugin 仓库里 5 个已上架插件的设置页迁到 HeroUI：agent-notify、dsh-chat、github-notify、pastedrop、smsforwarder-notify；`ui.mjs` 卡片不动。
- 顺带修掉内置久坐提醒设置页的字段变体：[RestSettings.tsx](../../src/app/pages/plugins/RestSettings.tsx) 里 Input / TextArea / Select 的 `variant="primary"` 改成 `variant="secondary"`，和外部插件设置页、以及「白卡上的字段用 secondary」的约定一致（primary 的 `--field-background` 在浅色主题下是白色、边框宽度 0，放在白色设置卡上等于隐形）。
- 插件仓库新增 `.agent/features/shared-ui/hero-ui-settings.md`（控件映射、扁平导出、尺寸与配色约定、测试 stub 方式），develop / README / SKILL / AGENTS 同步。
- 本仓库新增[外部插件设置页统一用HeroUI组件](../features/plugin-center/外部插件设置页统一用HeroUI组件.md)，并同步插件合同、React 架构、主题、项目结构、插件中心与设置等文档里「插件 UI 仍走 Radix」的旧描述。

## 关键取舍与坑

- **注入宿主同一份 HeroUI，而不是让插件自带**：Blob 模块不能 import 包，内置样式真源在宿主 `heroui.css`；插件只拿组件命名空间，外观与深浅色自动跟宿主，不额外发一份组件库。
- **输入 / 下拉用 `variant="secondary"`**：`primary` 变体底色是 `--field-background`（浅色下为白色）且默认边框宽度 0，放在白色设置卡上不可见；`secondary` 是 `--default` 浅灰底，和宿主设置页一致。
- **扁平导出优先**：`Switch.Content`、`Select.Trigger` 这类复合静态属性在 Blob 里能用，但插件 Node 单测把组件 stub 成字符串类型时构造不出静态属性；统一 `SwitchRoot` / `SelectRoot` / `SelectTrigger` 后，插件单测只需按组件类型找节点。
- **Radix 不能直接删**：其余 10 个插件与所有 Toast 卡片仍在用，根 Radix `Theme` 这个插件 UI 主题边界也还要保留，等卡片迁移完再收。
- **旧宿主兼容**：没有 `__CATRACE_HEROUI__` 的宿主上，新插件设置页会显式抛错并由宿主渲染「设置加载失败」；不做静默降级，避免界面悄悄退回原生控件难以排查。

## 验证

- 宿主：`pnpm typecheck`、`pnpm build`、`$env:CATRACE_PLUGIN_SOURCE='<插件仓库>'; node --test scripts/test-react-plugin-packages.mjs`（15 个插件真实 SSR）。
- 插件仓库：五个插件的 Node 单测（stub `__CATRACE_HEROUI__`）覆盖配置读写、RPC、防抖与卸载 flush。
- 界面效果需要用户在实际应用中确认：宿主侧注入随应用更新生效，插件新源码要按插件中心重新安装后才生效。
